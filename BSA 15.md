## Exercise 00 — Терминология

| № | Термин | Определение |
|---|--------|-------------|
| A | **REST** | **3)** Архитектурный стиль взаимодействия компонентов распределенного приложения в сети. |
| B | **Кеширование** | **8)** Увеличение производительности веб-приложений за счёт использования сохранённых ранее данных. |
| C | **Масштабируемость** | **5)** Способность системы, сети или процесса увеличивать свою производительность при добавлении ресурсов. |
| D | **Асинхронность** | **1)** Несовпадение, несогласованность с чем-либо во времени; неодномоментность, неодновременность. |

**Пояснение:**
- REST (Representational State Transfer) — это именно архитектурный стиль, предложенный Роем Филдингом в 2000 году, а не протокол (вариант 4 описывает протокол, что неверно).
- Кеширование напрямую связано с использованием сохранённых данных для ускорения работы.
- Масштабируемость — это рост производительности **при добавлении ресурсов** (горизонтальное/вертикальное масштабирование). Вариант 7 описывает оптимизацию без добавления ресурсов — это не масштабируемость.
- Асинхронность — это отсутствие синхронизации во времени, неодновременность процессов.

## Exercise 03 — Интеграция справочников

### Справочники, применяемые в UC04

| № | Справочник | Нужна ли интеграция | Обоснование |
|---|-----------|---------------------|-------------|
| 1 | Статусы персоны | Нет | Статусы жестко заданы в системе (`NEW`, `ACTIVE`, `ARCHIVED`). При создании новой персоны всегда устанавливается статус `NEW` по умолчанию. Внешняя система не участвует. |
| 2 | Статусы клиента | Нет | Аналогично статусам персоны — внутренние значения системы. |
| 3 | Каналы связи | Нет | Значения (`SMS`, `TELEGRAM`, `WHATSAPP`, `VK`) зашиты в бизнес-логику. При регистрации менеджером по умолчанию используется `SMS`. |
| 4 | Роли сотрудника | Нет | Проверка роли менеджера происходит внутри системы при авторизации. |

```json
      "value": "2026-10-20",
      "message": "Дата должна быть сегодня или позже."
    }
  ]
}
```

**Неуспешный ответ (мастер не существует или не имеет роли master):**
- Код состояния: `400 Bad Request`
- Тело ответа:
```json
{
  "error_code": "INVALID_EMPLOYEE",
  "message": "Сотрудник не существует или не имеет роли 'master'.",
  "errors": [
    {
      "field": "slots[0].employee_id",
      "value": 999,
      "message": "Сотрудник с ID 999 не найден или не является мастером."
    }
  ]
}
```

### Метод 3: Обновление слота (перенос визита клиента)

| Параметр | Значение |
|----------|----------|
| **HTTP-метод** | PUT |
| **URL-путь** | `/api/service-slots/{slot_id}` |
| **Параметры запроса** | `slot_id` (path parameter, BIGINT) — идентификатор слота |
| **Тело запроса** | JSON с новыми данными слота |
| **CRUD-операция** | Update |
| **Безопасный метод** | Нет |
| **Идемпотентный метод** | Да (PUT идемпотентен по определению) |

**Тело запроса:**
```json
{
  "slot_date": "2026-10-27",
  "start_time": "14:00:00",
  "employee_id": 102,
  "status_code": "CANCELLED",
  "cancellation_reason": "Перенос по просьбе клиента"
}
```

**Успешный ответ:**
- Код состояния: `200 OK`
- Тело ответа:
```json
{
  "slot_id": 5001,
  "slot_date": "2026-10-27",
  "start_time": "14:00:00",
  "employee_id": 102,
  "client_id": 301,
  "status_code": "BOOKED",
  "updated_at": "2026-10-23T11:00:00Z",
  "previous_values": {
    "slot_date": "2026-10-26",
    "start_time": "10:00:00",
    "employee_id": 101
  }
}
```

**Неуспешный ответ (слот не найден):**
- Код состояния: `404 Not Found`
- Тело ответа:
```json
{
  "error_code": "SLOT_NOT_FOUND",
  "message": "Слот с ID 5001 не найден."
}
```

**Неуспешный ответ (новый слот уже занят):**
- Код состояния: `409 Conflict`
- Тело ответа:
```json
{
  "error_code": "NEW_SLOT_CONFLICT",
  "message": "Выбранный новый слот уже занят другим клиентом.",
  "conflicting_slot": {
    "slot_date": "2026-10-27",
    "start_time": "14:00:00",
    "employee_id": 102,
    "client_id": 305
  }
}
```

### Метод 4: Отправка SMS об изменении слота

| Параметр | Значение |
|----------|----------|
| **HTTP-метод** | POST |
| **URL-путь** | `https://sms-gateway.external/api/v1/messages` |
| **Параметры запроса** | Отсутствуют |
| **Тело запроса** | JSON с данными SMS |
| **CRUD-операция** | Create |
| **Безопасный метод** | Нет |
| **Идемпотентный метод** | Да (через `external_id`) |

**Тело запроса:**
```json
{
  "recipient_phone": "+79003333333",
  "message_text": "Здравствуйте, Иван! Ваше время визита перенесено на 27.10.2026 в 14:00 к мастеру Дмитрию Сидорову. Приносим извинения за неудобства.",
  "channel": "SMS",
  "external_id": "slot_change_5001"
}
```

**Успешный ответ:**
- Код состояния: `202 Accepted`
- Тело ответа:
```json
{
  "message_id": "sms_890",
  "status": "ACCEPTED",
  "timestamp": "2026-10-23T11:05:00Z"
}
```

**Неуспешный ответ (шлюз недоступен):**
- Код состояния: `503 Service Unavailable`
- Тело ответа:
```json
{
  "error_code": "GATEWAY_UNAVAILABLE",
  "message": "SMS-шлюз временно недоступен. Сообщение поставлено в очередь."
}
```
